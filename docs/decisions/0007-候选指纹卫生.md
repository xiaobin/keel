# 0007 候选指纹卫生：onboard 负责让项目树对门稳定

- 状态：已实证（scripts/selftest.mjs 全绿）
- 日期：2026-10-23
- 前置：0005 §2 S1（门绑 projectRoot）；任务8 自验三连挂

## 问题

Comet 候选指纹门把 git porcelain/staged/脏文件内容纳入哈希（verify.checks 记录，verifier/revalidate 重算）。任何在 Run 中途变化的被跟踪文件都造成假漂移。selftest 连挂三次，根因各不同，全是「首跑一次性」污染：

1. **__pycache__/*.pyc 被 install.sh 提交进 git**——Python 首跑校验器时重建 pyc → 脏。
2. **.trellis/spec/ 骨架（testid.md、.gitkeep）由校验器首跑自动脚手架**——中途冒出未跟踪目录。
3. **.atlas/runs/last-check-error.log**——atlas 运行态产物，红写绿删，burn-in 时被误提交，Run 中变绿即删 → 脏（删除侧）。

atlas 是只读上游（AGENTS.md），不能改 install.sh/校验器，卫生责任落在 keel onboard。

## 决策

onboard.mjs 装配 .atlas 后执行三步，使用户项目树在首个 Run 前对门稳定：

1. .gitignore 补 `__pycache__/`、`*.pyc`、`.atlas/runs/`；已入库的同类文件 `git rm --cached`（随用户下次提交生效）。
2. burn-in：装完即跑一次 `atlas_check --fast`（不门禁），让 .trellis/spec 等首跑脚手架在 Run 前落位。
3. 输出提示用户提交 onboarding 产物后再 `keel start`。

## 实证

scripts/selftest.mjs：临时物理路径空项目 → git init → config 夹具 → onboard → brief/PRD 夹具 → start → confirm → candidate 提交 → build --summary → next → verify → next → confirm → next → 断言 archive/done+archived=true。全绿（sv8）。作为 CLI/应用包改动的回归门：`npm run selftest`。

## 边界

- 新项目首个 Run 前的「提交 onboarding 产物」仍是用户动作；selftest 用 assets 提交模拟。
- .trellis/spec 内容属 atlas 管理的应然资产，入库跟踪是对的——只是必须在 Run 前落位。
