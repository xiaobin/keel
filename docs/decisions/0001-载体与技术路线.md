# 0001 — 载体与技术路线

- 日期：2026-10-23
- 状态：已接受

## 决策

1. Keel 是**全新独立项目**，不做 atlas/comet 的桥接件或 fork。
2. **运行时：Comet Native 模式**——复用其状态机、验收、可恢复归档、Builder/Verifier 身份分离；不走 Classic 的 OpenSpec 五阶段。
3. **治理层：Atlas 的 Project Harness 体系**（三环资产 / atlas_check 门禁 / E2E 评审台 / 变异证明）下沉为 Native 工作流中的资产与门禁环节，Python 校验器初期作为外部工具调用，不重写。
4. 发布目标：GitHub（开源，MIT）。npm 裸名 keel 已占，若发 npm 用 scoped 名。

## 理由

全流程工作流最难的部分（状态持久化、中断恢复、SDK、Eval、Dashboard、分发）Comet 已完成；Atlas 的护城河在治理模型而非运行时。反向方案等于重写一个 Comet。
