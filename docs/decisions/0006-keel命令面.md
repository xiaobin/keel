# 0006 keel 命令面：keel 动词封装调度，不复制 comet 命令

- 状态：已实证（keel-cli-change 全程走通并归档）
- 日期：2026-10-23
- 前置：0005 §3 协议要点、§4 落点；用户指示「不要复制 comet 的命令，要基于 keel 命令」

## 决策

调度封装做成 keel 自己的命令面 `bin/keel.mjs`（package.json bin: keel）。操作者只用 keel 动词，comet 命令树不外露。

## 命令面

| 命令 | 语义 | 内部驱动 |
|---|---|---|
| `keel onboard <change>` | 开户（资产+.atlas+start-request） | scripts/onboard.mjs |
| `keel start <change>` | 启动 Run | dispatch --application-file |
| `keel status <change>` | 状态与待办 | dispatch inspect |
| `keel next <change>` | 推进 Runtime 可自行部分：宿主检查走 native next；扩展 Action 自动 execute（keel-governance-script）；遇 Builder/Verifier 交接或用户等待则停下并提示对应 keel 动词 | native next / dispatch execute |
| `keel build <change> --payload f.json` | Builder 交接；payload 只含业务字段（summary/acceptanceReview/checks/knownLimits/verificationChecks） | claim+record-outcome |
| `keel verify <change> --payload f.json` | 独立 Verifier 裁决；payload 只含 verdict/summary/acceptance/risks | claim+record-outcome |
| `keel confirm <change> --summary s` | 确认当前等待：shape 两步、verify accept-result，守卫值自动取自 commandAlternatives | native next |
| `keel archive <change>` | 归档 | native archive |

## 协议要点内化的位置（0005 §3 → CLI）

1. claimToken：CLI 生成 `<actionId>-<sessionId>-<ts>`，调用方不接触。
2. record-outcome 形状（字段全在 outcome 内）：claimAndRecord 统一组装。
3. outcomeId 唯一占位：同上带时间戳，OUTCOME_CONFLICT 不可能。
4. Builder 校验三项：submittedAt 用 new Date().toISOString()；candidateCommit 取 git HEAD；acceptanceReview evidence 空数组前置拒绝。
5. verify.checks 走 native next：keel next 内部分流，execute 只用于扩展。
6. Verifier 三绑定：candidateId/attempt/iteration 从 dispatch next runnerAction 取，sessionId/verifierExecutionRef 固定 'verifier'。
7. 请求文件一律 os.tmpdir()（mkdtemp），绝不进项目根。
8. comet 二进制只认仓内构建（COMET_BIN 或 ../comet/bin/comet.js），全局 PATH 版本禁用。

另加 S1 防御：projectRoot 必须等于其 realpath，软链路径直接拒绝（0005 §2 S1 假漂移）。

## 边界

- build/verify payload 的业务内容（验收证据、裁决理由）仍是操作者责任，CLI 只保证协议形状。
- 多子任务 Supervisor 链路、revise-requirements 回退、integration-repair 循环未封装，需要时再加动词，不预先抽象。
