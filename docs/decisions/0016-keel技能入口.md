# 0016 — Keel 项目技能入口

- 日期：2026-10-27
- 状态：已决定
- 前置：0002（Native 挂点）、0010（Atlas 载荷内置）、0014（init 项目接入）、0015（Keel agent 指引挂载）
- 依据：用户反馈「项目没有 /keel技能啊」

## 决定

`keel-h init` 在接入门通过后，除挂载 AGENTS 指引外，还安装一个名为 `keel` 的薄 Skill；`onboard` 复用 init，因此行为一致。Skill 只负责把用户意图路由到 `keel-h` 并重申关键人机边界，不复制 Comet 调度协议，不安装 Atlas 独立模式技能。

同一份载荷写入两个宿主位置：

- `.agents/skills/keel/SKILL.md`：Agent Skills / Pi，Pi 显式调用为 `/skill:keel`；
- `.claude/skills/keel/SKILL.md`：Claude Code，调用为 `/keel`。

Skill 是项目受管文件，含 `<!-- KEEL:MANAGED -->` 标记。管理规则：

- 目标不存在时创建；受管旧版由后续 `init/onboard` 更新；内容一致时不动。
- 写入前先检查两个目标，任一已有同名文件没有受管标记则整体拒绝写入，保留原文件并提示人工处理。
- `keel-h update` 的边界不变，仍只升级 `.atlas/`；Skill 和 AGENTS 指引通过重跑 `init/onboard` 刷新。
- npm 包白名单加入 `skills/`，保证全局安装后的 init 能取得载荷。

## 验证

- `npm run selftest:init`：双宿主安装、源文件一致、幂等、任一宿主非受管 Skill 拒绝覆盖且另一宿主不写。
- `npm run selftest`：onboard → archive 全链回归。
- `npm pack --dry-run --json`：确认 `skills/keel/SKILL.md` 与安装逻辑进入发布包。
