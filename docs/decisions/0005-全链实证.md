## 2. Comet 尖刺（新发现，补充 0002 §6.3）

### S1. 候选门绑定 projectRoot 字符串形式——软链路径下必现假漂移（严重）

候选指纹门（native-portable-checks.ts readNativeCheckInputObservation :859-932）把
projectRoot **字符串本身**纳入哈希。macOS /tmp→/private/tmp 软链下：
run 启动时绑定逻辑形 /tmp/…，而 native next/archive CLI 经
projectRootFrom/explicitProjectRootFromCurrentWorktree（native-cli-shared.ts:177-196）
归一为物理形 → verify.revalidate 重算门不匹配 →
NativeSdkCandidateDriftError「候选实现已变化或无法完整复核」。
**规避：keel 开户与调度一律要求物理路径；文档化警告 macOS /tmp、/var 均为软链。**

### S2. candidate-drift 后的 loop-stop 无向前出口（严重）

verify.revalidate 漂移失败后转场（native-sdk-application.ts:2363-2375）建 verify.stop
等待，choices 仅 ['repair']，continuation（native-portable-continuation.ts:916-934
resolve-loop-stop）备选仅 revise-implementation / revise-requirements——
**即使最后一次 Verifier 裁决是 pass，也没有"重新确认后直接归档"的选项**。
假漂移场景下用户被卡在只能"修"的等待里。0002 §6.3 缺口表补充此项。

### S3. 已确认的旧项（本 run 再次实证）

Shape 阶段无扩展 scope（G1）、Archive 阶段无扩展 scope（G2）、扩展不能新增自定义 Wait（G3）。

## 3. Runtime 协议操作要点（keel 侧调度器/文档必须内化）

本次全链踩出的协议事实，全部有源码或实证依据：

1. **claimToken 是调用方自报的任意非空字符串**（runtime-action.ts:162-170）；
   record-outcome 的 outcome.claimToken 必须与 claim 时完全一致（纯字符串比对，:227-228）。
   占位符原样发出就会成为真 token。
2. **record-outcome 请求形状**：{operation, runId, outcome:{actionId, attempt, inputHash,
   claimToken, outcomeId, status, output}}——actionId 等字段在 outcome 内部，顶层出现即
   INVALID_REQUEST「不支持的字段」。
3. **被拒 outcome 也占位**：OUTCOME_REJECTED 后同 outcomeId 改内容重提交 →
   OUTCOME_CONFLICT「同一结果标识不能提交不同内容」。修正错误必须换新 outcomeId。
4. **Builder output 硬校验**（native-sdk-application.ts:464-489 +
   native-builder-acceptance-review.ts）：
   - submittedAt 必须满足 new Date(x).toISOString() === x（毫秒+Z 结尾，Python 需
     isoformat(timespec='milliseconds').replace('+00:00','Z')）；
   - checks[].result ∈ passed|failed|not-run（不是 pass）；
   - acceptanceReview 必须覆盖每条验收且 status=implemented-with-evidence 且
     evidence 为非空字符串数组（空数组视为 not ready）。
5. **verify.checks 由 native next 宿主侧执行**（带保护执行记录
   native-sdk-check-execution.ts），不是 dispatch execute；dispatch execute 仅用于
   应用注册的扩展执行器（如 keel-governance-script）。
6. **Verifier 绑定三条件**（native-sdk-application.ts:547-574）：claim.sessionId ≠
   builder 执行引用；output.candidateId == state.builder_handoff.candidate_id；
   output.verifierExecutionRef == claim.sessionId。
7. **dispatch 请求 JSON 一律放项目外**：指纹门含 git porcelain + dirty 文件内容 digest，
   项目根内的临时文件反复改写 = 自造漂移（0004 教训，本 run 全程 /tmp/keel-req-e2e/）。
8. **全局 PATH 上的 comet 可能是另一版本**：全程用仓内构建
   node <comet>/bin/comet.js（0.5.0），混用会有 schema/命令集漂移风险。
