# 发布 @benym/keel-h 到 npm

> 前置：npm 账号已 `npm login`（registry.npmjs.org）。一次性。

## 每次发布

```bash
cd keel
npm run selftest        # 回归门：全链绿才准发
npm version patch       # 或 minor/major；自动打 git tag
npm publish             # prepublishOnly 自动重建 application.json
git push --follow-tags
```

用户侧安装：`npm install -g @benym/keel-h`（本地命令 `keel-h`）。

## 硬性约束

- **包名**：已定为 `@benym/keel-h`（scoped）。背景：`keel-harness` 在 npm 上被无关项目占用（2026-08 起），裸名 `keel` 亦被占，故 scoped 化；本地命令 `keel-h`（package.json `bin` 映射）。
- **comet 依赖**：已改为 `@rpamis/comet: ^0.5.0`（registry 版，2026-10-23 由 benym 发布）。
  keel 命令面默认解析 `node_modules/@rpamis/comet/bin/comet.js`，与 application.mjs 的 import 同源，不会版本劈叉。
  comet 升 minor 后须跑 selftest 再决定是否放宽版本范围。
- **vendor/atlas 快照**：随包下发（files 白名单含 vendor/）。升级 atlas 上游时重新快照并跑 selftest（参见 vendor/atlas README 与 0010 决策）。
- **不要恢复 `file:../comet` 依赖**——registry 包里的 file: 依赖会在用户机器上解析失败。

## 首次发布清单

1. `npm login`
2. 包名已定 `@benym/keel-h`（见上），无需再改
3. `npm run selftest` 绿
4. `npm publish --access public`（scoped 包必须显式 public）
5. 改 README 与 docs/安装使用手册.md 的安装命令为最终包名
